# Calculator V2 — 理性购房决策器

> 工具的核心问题从「能买多少」改成「**理性该买多少 + 该不该买**」。

## 1. 产品定位

### 1.1 它回答的问题

用户走完一遍流程，应当能回答自己三个问题：

1. **我该看多少钱档次的房？** → 房价区间（舒适 / 平衡 / 极限）
2. **那我手里应该攒多少？** → 现金需求拆解 + 应急金建议
3. **这事到底该不该做？** → 买 vs 租 break-even（首套显示）

### 1.2 它不做的事

- ❌ 不替用户做"买/不买"判断
- ❌ 不分流弹窗（外籍买家也走同一流程）
- ❌ 不收集用户当前实际租金（避免偏差污染）
- ❌ 不让用户自己输入"心仪房价"（结果由系统倒推）
- ❌ 不做 lead 分流前的"目的/类型偏好"等装饰字段

### 1.3 产品基调

**让数字说话，不家长式干预。**

外籍买首套显示"还差 S$ 1,280,000 现金"——这是真相，工具该给得起这个力度。
用户看到数字会自己判断（咨询税务顾问 / 等拿 PR / 放弃 / 全款），不需要工具替他难过。

## 2. 用户流程

```
单入口 hero
  ↓
Step 1 · 身份信息（3 题）
  ↓
Step 2 · 财务信息（2-3 题，外籍跳过 CPF）
  ↓
Step 3 · 计划（1 题）
  ↓
Loading
  ↓
结果页（可在线微调 4 个参数实时重算）
```

**最多 7 题，最少 6 题**（外籍）。

## 3. 问卷设计

### Step 1 · 您和这次买房

| # | 字段 | 类型 | 默认 |
|---|---|---|---|
| Q1 | **身份** | 4 选 1（SC / PR / 外籍 WP / 外籍无身份） | — |
| Q2 | **名下已有几套住宅**（含全球） | 3 选 1（0 / 1 / 2+） | — |
| Q3 | **主申请人年龄** | 滑块或滚轮（21-65） | **35** |

### Step 2 · 您的钱

| # | 字段 | 类型 | 默认 | 备注 |
|---|---|---|---|---|
| Q4 | **家庭税前月收入**（含配偶） | 5 档区间 | — | 5K-15K / 15K-20K / 20K-30K / 30K-50K / 50K+ |
| Q5 | **可动用现金**（不含 CPF） | 5 档区间 | — | <20万 / 20-50万 / 50-100万 / 100-200万 / 200万+ |
| Q6 | **CPF OA 余额** | 4 档区间 | 按身份预填 | **外籍跳过此题**（CPF=0） |

### Step 3 · 您的计划

| # | 字段 | 类型 | 默认 | 备注 |
|---|---|---|---|---|
| Q7 | **预期购入时间** | 3 选 1 | — | 半年内 / 1 年内 / 1 年以上 |

> Q7 不影响计算，仅作为 lead 优先级标签。

### 砍掉的字段（明确排除）

- ❌ 贷款年限 → 默认 30 年
- ❌ 持有年数 → 默认 7 年
- ❌ 现有月供债务 → 默认 0
- ❌ 购房目的（自住/投资/升级）
- ❌ 房产类型偏好（新盘/二手）
- ❌ 婚姻状态 / 配偶身份（合并到"家庭收入"里处理）
- ❌ 父母赞助金额（已隐含在"可动用现金"里）

## 4. 默认值与背后逻辑

| 参数 | 默认 | 选这个数的理由 |
|---|---|---|
| **贷款年限** | **30 年** | 新加坡银行最长允许；60% 买家实际选择；月供占比最低 → 通过 TDSR 概率最大 → 工具不会过早给"买不起"假阴性 |
| **持有年数** | **7 年** | 跨过 SSD 4 年红线；新加坡私宅自住中位持有 7-9 年；落在 break-even 数学接近过去 10 年实际涨幅的甜蜜点 |
| **现有月供债务** | **0** | 多数新加坡年轻人本就为 0；可在结果页输入修正 |
| **年龄** | **35** | 新加坡首套 condo 买家中位年龄 |
| **CPF OA** | 按身份预填 | SC ~20 万；PR ~10 万；外籍 0 |
| **市场利率** | **1.65%** | 当前 SORA 浮动利率参考值 |
| **TDSR 压力利率** | **4%** | MAS 监管要求 |

> ⚠️ 边界处理：35 岁 + 30 年 = 65，刚好踩 LTV 75% → 55% 悬崖。
> 40 岁 + 30 年 = 70，触发降到 55%。
> 这种情况下系统自动算出 LTV 55%，结果页提示"可缩短到 25 年恢复 75% LTV，但月供会上升 SGD XXX"。

## 5. 结果页输出

结果页从上到下三大块：

### Block 1 · 理性房价区间

```
┌─────────────────────────────────────┐
│  您理性可支持的房价                  │
│                                      │
│  舒适区   S$ 100 万 – 130 万        │
│  ─────  月供占月收入 ≤ 30%          │
│                                      │
│  平衡区   S$ 130 万 – 150 万   推荐  │
│  ─────  月供占月收入 ≤ 35%          │
│                                      │
│  极限区   S$ 150 万 – 170 万        │
│  ─────  月供占月收入 ≤ 55%（MAS）   │
└─────────────────────────────────────┘
```

- 3 档显示，**默认推荐"平衡"**（不推"极限"）
- 极限是 MAS 监管允许，但工具明确标注"日常生活会吃紧"
- 每档可点击，下方 Block 2 / Block 3 联动重算

### Block 2 · 现金需求拆解（针对当前选中档位）

```
┌─────────────────────────────────────┐
│  买"平衡区"的房需要准备的现金        │
│                                      │
│  首付现金部分（5% 必须）   S$ 6.5万  │
│  CPF 可补（首付的 20%）   S$ 19.5万  │
│  BSD 买方印花税（累进）   S$ 3.4万   │
│  ABSD 额外印花税（PR 5%）  S$ 6.5万  │
│  律师/估价/杂费           S$ 0.4万   │
│  ─────────────                       │
│  交易现金需求             S$ 16.8万  │
│  + 应急金（12 月家庭开销） S$ 9.6万  │
│  ────────────────                    │
│  您实际应有现金 ≥        S$ 26.4万  │
└─────────────────────────────────────┘
```

- CPF 自动按身份扣除（外籍 CPF=0 时整行隐藏）
- BSD/ABSD 必须现金支付，明确标注
- **应急金独立一项**，不让用户忽略买完后的流动性

### Block 3 · 买 vs 租 break-even（仅首套显示）

```
┌─────────────────────────────────────┐
│  那这套房买不买划算？                │
│                                      │
│  同档位市场月租 ⓘ                    │
│  ┌────────────────┐                  │
│  │  S$ 4,500      │ ← 可编辑          │
│  └────────────────┘                  │
│                                      │
│  打算住几年？  [5][7][10][15] 年      │ ← 默认 7
│  贷款年限      [20][25][30] 年        │ ← 默认 30
│  房贷利率      [滑块 1.5% – 4%]       │ ← 默认 1.65%
│                                      │
│  Break-even：年涨 ≥ 2.0% 买划算       │
│  ─────                              │
│  这一带过去 10 年实际涨 2.8% / 年    │
│  您怎么看未来 7 年？                  │
└─────────────────────────────────────┘
```

- **关键创新：4 个参数（租金/年数/年限/利率）结果页全可调，实时联动**
- 输出**单一数字**：break-even 涨幅 X%
- 不给"买/租"建议，给出**比较锚点**（区域历史涨幅）让用户自己判断
- 二套及以上**不显示此 block**（投资逻辑，租金对比无意义）

### Block 4 · 诊断面板（仅在不可行时显示）

如果用户的目标在"极限区"以上仍买不起，给出 3 条出路建议：

**一般用户（缺现金 < 50 万）：**
- 再攒 S$ XX 万 / 父母赞助补足
- 降到 S$ Y-Z 万预算区间
- 延贷款到 30 年（如还没满）

**外籍用户（缺 100 万+）：**
- 这个差额对应 ABSD 60% 政策，不是攒钱能解决的
- **拿到 PR 后再买**，ABSD 降到 5%（缺口降到 ~10 万）
- 全款（如有 200 万+ 现金）

## 7. 实现 / 工程对接

### 7.1 可复用的现有代码

| 文件 | 现有函数 | V2 中如何用 |
|---|---|---|
| [lib/tax/tdsr.ts](../lib/tax/tdsr.ts) | `solveMaxPurchasePrice` | 算极限区（55%）|
| [lib/tax/tdsr.ts](../lib/tax/tdsr.ts) | `isFeasibleAtPrice` (file-local) | 算舒适区（30%）和平衡区（35%）需要的"修改版" |
| [lib/tax/tdsr.ts](../lib/tax/tdsr.ts) | `buildOutput` (file-local) | 给定房价输出全部数字（首付/BSD/ABSD/月供）|
| [lib/tax/seed.ts](../lib/tax/seed.ts) | `SEED_TAX_RATES` | BSD/ABSD/LTV 全套查表 |

### 7.2 需新增的引擎逻辑

- `solveByMonthlyRatio(ratio, params)` —— 在月供占月收入 ≤ ratio 的约束下二分搜索房价。**目前 `solveMaxPurchasePrice` 隐含 ratio=55%**，需要扩展为可参数化。
- `computeBreakEven(price, rent, years, interestRate, ...)` —— 计算 break-even 年化涨幅
  - 输出：g* 使得 H 年后买房净资产 = 租房净资产
  - 模型：买方 = 房价 × (1+g)^H − 卖房成本 − 剩余贷款 − 累计利息/物业税/维护
  - 租方 = (首付+税) × (1+r)^H + 累计月省下投资 − 累计租金
  - 替代投资回报 r 默认 5%（保守的标普 500 长期）
- `regionalAppreciationLookup(district)` —— 区域历史涨幅参考（先用 URA PPI 全市数据，未来按地段细分）
- `medianRent(priceBucket, propertyType)` —— 市场租金中位数（数据源待定）

### 7.3 待定的数据问题

**租金中位数从哪儿来** —— 这是这个版本的卡点：

| 选项 | 优劣 |
|---|---|
| URA 季度租赁合同公开数据 | 官方权威，但聚合度低（需自己处理） |
| PropertyGuru / 99.co 爬数据 | 实时新鲜，但合规风险 |
| Hard-coded 区间档（150万房 = 4500租 之类） | MVP 快，但精度低 |

**MVP 推荐：hard-coded 5 档**（按房价段映射月租中位数）。
v2 再考虑接 URA 数据。

### 7.4 API 改动

`/api/v1/calculator/compute` 改返回结构：

```ts
{
  ok: true,
  data: {
    comfortable: { price_range: [...], cash_needed: ..., monthly: ... },
    balanced:    { price_range: [...], cash_needed: ..., monthly: ... },  // ← 推荐
    aggressive:  { price_range: [...], cash_needed: ..., monthly: ... },
    is_first_property: boolean,
    break_even: {
      median_rent: number,
      default_years: 7,
      default_rate: 0.0165,
      default_tenure: 30,
      g_star: 0.020,
      regional_historical: 0.028,
    } | null,  // null when not first property
  }
}
```

## 8. 关于 lead-gen 与商业模式

这套设计**比现版本 lead 数量少**，但**质量高**。原因：

- 砍掉"购房目的/类型/时间线（保留半年内/1年内/1年以上）"等装饰字段 → 用户填得快，但中介收到的画像更准
- "让数字说话" → 外籍/低收入用户看到"还差 100 万"会自己离开，留下来的是真有购买力的
- Break-even 模块 → 用户已经理性判断"该买"，再去找中介转化率更高

中介付费意愿评估：
- 现版本：用户填完就有"最大可买 190 万" → 中介收到的 lead 是"年收入 17K 但被工具暗示能买 190 万的人"——很多是不可成交线索
- 新版本：用户走完知道自己应该看 130-150 万、需要 26 万现金、break-even 2% → 中介收到的是已经做完家庭作业的人

## 11. 验证 / 验收标准

工具上线前，**用以下 3 个真实画像走一遍**，结果应当落在合理区间：

| 画像 | 应当输出（大致） |
|---|---|
| **PR · 月入 17K · 现金 35 万 · CPF 20 万 · 35 岁 · 首套** | 平衡区 130-150 万；需要现金 ~28 万；break-even ~2% |
| **SC · 月入 25K · 现金 60 万 · CPF 35 万 · 32 岁 · 首套** | 平衡区 180-220 万；需要现金 ~35 万；break-even ~2.2% |
| **外籍 WP · 月入 20K · 现金 80 万 · CPF 0 · 38 岁 · 首套** | 极限区都买不起 150 万；缺 ~70 万现金；诊断给"等 PR" |

如这 3 个 case 的数字明显偏离常识，引擎参数或公式有问题。
